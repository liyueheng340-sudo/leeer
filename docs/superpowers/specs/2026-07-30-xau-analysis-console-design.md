# XAU Analysis Console 设计

## 目标

在本机提供一个桌面优先的浏览器控制台，帮助人工分析 Bitget MT5 的 XAUUSD 行情。它把只读报价、已核验事件状态和 Qwen 研究结果放在同一页，给出可追溯的观察、等待条件和情景计划。

系统不下单、不修改 MT5 参数、不持有账户凭证，也不把模型文字当成已验证的交易事实。

## 现状与依据

- 上游底座固定为 `TauricResearch/TradingAgents`，提交为 `a33fd4c0f134485a43553a2c23a63cb14adbd88f`。
- `D:\XAU\scripts\mt5_xau_market_context_once.py` 已能生成 Bitget MT5 的只读 XAUUSD 快照。
- 上游框架没有网页界面，且其 Yahoo Finance 代理报价不能替代 Bitget MT5 报价。
- Qwen 国际版已配置。快速模型是 `qwen3.7-max`，深度复盘模型是 `qwen3.8-max-preview`。
- 已观察到未受约束的模型会引用未提供的数据和在重大事件前给出操作建议，因此模型输出必须经过事实闸门。

## 范围

### 第一版包含

1. 本地网页控制台，只监听 `127.0.0.1`。
2. 一键刷新只读 MT5 行情快照。
3. 报价、点差、快照时间、数据年龄、M1/M5/M15 结构摘要和市场状态。
4. 事件状态卡。事件事实不可用时明确显示“未核验”，不会伪装成空白或低风险。
5. Qwen 实时简报和深度复盘两个异步任务。
6. 事实闸门、报告接受或拒绝状态、可追溯简报历史。
7. 中文优先的深色专业盘面，适配 1440px 以上桌面显示。

### 第一版不包含

- 任意买入、卖出、平仓、改单、仓位读取或账户设置。
- 自动交易、信号推送到 MT5、复制交易或策略参数优化。
- 把 Yahoo、DXY、新闻标题或模型记忆伪装为 Bitget XAUUSD 实时报价。
- 复杂指标墙、EA 参数表或为了视觉效果而添加的动画。

## 页面结构

顶部状态栏显示产品名、Bitget MT5 身份匹配状态、当前报价、市场状态、快照 UTC 时间和数据年龄。

主视图区分为三个层次：

1. 左侧市场面板显示 bid/ask、点差、M1/M5/M15 结构、波动和会话信息。
2. 右侧风险面板显示事件状态、快照有效性和模型任务状态。红色只表示阻断或数据异常，琥珀色表示等待或未核验，青绿色表示已验证且可分析。
3. 下方行动面板只显示四种结论：`ANALYSE`、`WATCH`、`WAIT`、`BLOCKED`。每个结论必须附带依据、失效条件和下一步观察条件。

主操作是“刷新 MT5 并生成简报”。深度复盘是次级操作，清楚标明可能耗时较长。页面没有买卖按钮。

两个操作都必须提供可见进度。点击后先创建本地任务并返回任务编号，再依次显示“读取 MT5 快照”“校验数据与事件”“提交 Qwen”“校验报告”“完成”或具体失败原因。任务状态与阶段耗时写入本地任务记录，浏览器刷新后仍能恢复显示，不能只依赖前端计时器。

## 数据和决策流

```text
用户刷新
  -> 只读 MT5 快照
  -> 快照规范化与新鲜度检查
  -> 已核验事件上下文
  -> 事实闸门
  -> Qwen 异步研究任务
  -> 结构化输出校验
  -> 接受的简报或拒绝原因
  -> 浏览器页面与本地历史
```

### 快照

快照的唯一报价事实源是现有 MT5 脚本生成的本地 JSONL。控制台只读取其输出，不导入、调用或暴露 MT5 交易接口。快照必须携带捕获时间、交易品种身份和来源标识。

数据过期、品种身份不匹配、市场关闭或快照解析失败时，系统进入 `BLOCKED`，不调用模型。

### 事件上下文

事件层只接受带来源和时间的核验记录。第一版允许事件层处于“未核验”状态，此时系统进入 `WATCH`，模型只能写观察和等待条件，不能生成方向性开仓计划。

当已核验的高影响事件在预设窗口内，系统进入 `WAIT`。这是一条确定性规则，不由模型覆盖。事件层的后续数据源只使用官方日历或经确认的授权源，并将来源、抓取时间和事件时间同时展示。

### 模型任务

`qwen3.7-max` 用于实时简报。`qwen3.8-max-preview` 仅由用户主动启动，用于深度复盘。两者都作为后台任务运行，网页持续可用。

模型只接收规范化快照、事件状态和允许引用的事实。TradingAgents 提供多角色研究框架和报告结构，但不拥有报价真相，也不能绕过事件闸门。

### 事实闸门

事实闸门在模型前后各执行一次：

1. 前置闸门拒绝过期、身份不匹配、市场关闭和事件等待状态。
2. 后置闸门要求结构化结果包含结论、依据、失效条件和观察条件。
3. 后置闸门拒绝引用未提供的价格源、未核验事件、虚构指标和事件窗口内的直接开仓指令。
4. 被拒绝的报告不进入决策区。页面只显示拒绝状态和原因，原始文本不作为交易建议展示。

闸门能限制错误传播，不能证明模型有稳定盈利能力。页面必须保留这一边界。

## 视觉系统

界面采用深色 OLED 操作台风格：近黑背景、低饱和深蓝灰分层、克制的状态色和清晰数字排版。色彩只表达状态，不用于装饰。价格、时间和风险状态优先于长段落文字。

布局桌面优先，避免模仿 MT5 的参数表。图标统一使用简洁 SVG，卡片只保留必要边界与轻微层次，不使用大面积发光、玻璃拟态或噪声背景。数据加载时显示骨架状态和任务耗时，避免用户误以为页面卡死。

## 本地边界与文件边界

控制台作为 TradingAgents 旁的独立本地 sidecar，实现文件不改动 `tradingagents/` 上游包逻辑。它复用现有 MT5 快照输出和本地 Qwen 配置，但不复制密钥到浏览器、不在日志中写入密钥，也不向局域网暴露服务。

报告、任务元数据和拒绝原因写到独立本地目录。每条记录保留快照时间、事件状态、模型名和接受结果，便于人工复盘。

## 验收标准

1. 本机能用一个启动入口打开控制台，默认只绑定 `127.0.0.1`。
2. 点击刷新后，页面显示来自 MT5 的快照时间、数据年龄、bid/ask 和点差。
3. 快照过期、身份不匹配、市场关闭或事件等待时，页面不触发模型简报，并显示具体原因。
4. 实时与深度任务都不会冻结页面。任务完成后，只有通过后置闸门的简报能出现在决策区。
5. 页面能查看简报历史及每条报告的接受或拒绝状态。
6. 两个按钮在任务运行时显示当前阶段、开始时间和已用时间，网页刷新后状态仍然可见。
7. 代码和依赖扫描确认没有订单、持仓修改、SL/TP 修改、账户登录或 MT5 配置写入路径。
8. 在 1440px 宽度下，报价、事件状态、行动结论和主操作无需滚动即可同时看到。

## 验证方式

实现完成后执行三类验证：

1. 运行一次只读快照和控制台接口测试，确认产生的状态与快照时间一致。
2. 用过期快照、事件等待和模型越界文本进行小型固定样例测试，确认页面分别显示 `BLOCKED`、`WAIT` 和“报告被拒绝”。
3. 搜索代码中的交易变更调用，并人工检查启动命令、网络绑定和浏览器页面。
