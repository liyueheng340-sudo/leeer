# XAU 控制台：速度/稳定性审查与升级方案（2026-07-31）

审查范围：local_console 全部 14 个模块 + scripts + 52 个历史任务 JSON。
标注约定：【事实】= 数据/代码直接支持；【推断】= 合理延伸；【候选假设】= 未验证。

---

## 一、性能画像（52 个历史任务实测，事实）

| 阶段 | brief（n=44） | deep_review（n=8） |
|---|---|---|
| SNAPSHOT | P50 1.31s / P90 2.33s | P50 1.25s |
| GATE | ~0.01s | ~0.01s |
| **MODEL** | **P50 38.9s / P90 66.3s / max 526s** | **P50 86.4s / P90 90.3s / max 181.7s** |
| VALIDATE | ~0.01s | ~0.01s |
| 总耗时 | P50 40.5s | P50 87.2s |

- **MODEL 阶段占总耗时约 97%（事实）**。非 LLM 路径（快照+闸门+校验）合计约 1.3s，继续压缩无实质意义。
- MT5 合并采集今日实测（热终端）：1.40–1.41s，与文档记录一致（事实）。
- 真实 prompt 约 5.1KB（约 2K token 量级），已属精简；prompt 瘦身无显著收益（事实）。

## 二、稳定性发现（事实）与已实施修复

### 失败模式分布
- brief REJECTED 3/44（6.8%）：全部为"报告正文必须使用中文"（risk_note ×2、next_observation ×1）。
- deep_review FAILED 3/8（37.5%）：全部为模型超时（180s 边界）。
- brief FAILED 2/44：detail 为"Qwen 分析失败"，无更细日志区分围栏解析失败 vs 网络故障（诚实声明：无法归因）。

### 本轮已修复（168 测试全过）
1. **P1 — 损坏 JSON 拖垮全部 API（jobs.py）**：`fail_stale_jobs` 解析目录内每个文件且无异常容忍；任一损坏 .json 会让所有轮询 API（status/history/jobs）持续崩溃，且服务启动即失败。已修复：损坏文件跳过（含 TypeError 路径），`list_recent` 同步补齐。
2. **P2 — 模型围栏输出误判故障（brief.py）**：模型偶发 ```json 围栏或夹带文字时原解析直接失败 → 重试 → FAILED。新增 `_parse_model_json`：原文 → 围栏内 → 首尾大括号子串三级候选；内容契约仍由 validate_report 严格把关。
3. **P3 — REJECTED 主因定向缓解（brief.py，prompt 1.1.1）**：新增规则"中文字段只允许白名单英文缩写（TP/SL/ATR/XAUUSD/DXY/FOMC/CPI/NFP/PCE/M5/M15/H1/H4），其它英文单词一律拒绝"。预期降低 6.8% 的 REJECTED 率，效果可经 review.py 的 prompt_version 情境统计验证（验证闭环已具备）。
4. 新增 8 个测试（7 个解析容错 + 1 个损坏文件容忍），版本锁测试同步更新。

### 激活条件
- Python 修复（jobs.py / brief.py）需**重启控制台**生效；前端静态改动此前已即时生效。
- 启动器 `run_xau_analysis_console.py` 的"接管"逻辑是复用而非重启——需先停掉旧进程再启动。

## 三、升级方案（黄金交易员视角）

### A. 事实层增强（确定性计算，零模型成本，低风险，建议优先）

| 方案 | 内容 | 标注 | 工作量 |
|---|---|---|---|
| A1 交易时段上下文 | facts 注入 session_context：当前时段（亚洲/伦敦/纽约）、距伦敦定盘（10:30/15:00 London）、COMEX 开盘（8:20 ET）的分钟数。纯时间函数，不进闸门 | 事实：定盘机制公开存在；推断：定盘/COMEX 时段波动放大是交易员共识，可提示模型在事件窗口前收敛档位 | 小（新模块 ~60 行 + facts 注入 + 测试） |
| A2 关键价位层 | 从现有 latest_closed_bars 确定性计算：前日高/低、本周高/低、最近摆动点、最近整数关口（±50）及距离 | 事实：数据已具备；推断：给模型"位置感"可减少档位悬空，与 ATR 校验互补 | 小（~80 行 + 测试） |
| A3 点差常态分位 | tick_health.spread_median 相对近 N 次任务的分位数（数据已在 jobs/runlog 中） | 事实：当前只有绝对阈值 0.8；推断：分位数更贴近"该经纪商该时段的常态 vs 异常" | 小（读历史 + 统计） |

### B. 模型阶段提速（唯一实质杠杆，需用户决策）

| 方案 | 证据 | 代价/风险 | 建议 |
|---|---|---|---|
| B1 deep 超时 180s→240s | 3/8 失败全在 180s 边界（事实） | worker 阻塞更久；stale 阈值随动到 270s（代码自动联动，已核实） | 可试一周，用 FAILED 率验证 |
| B2 quick 模型换更快档位 | qwen3.7-max P50 38.9s（事实） | 质量/成本三角，无数据支持更快模型质量不降（推断） | 用户决策，不建议盲目换 |
| B3 流式输出 | MODEL 40-90s 无中间反馈（事实） | 工程量大；收益是感知速度而非实际速度（推断） | 候选，非优先 |

### C. 测量层增强（纪律：均不构成 edge 证据）

- C1 MFE/MAE（最大有利/不利偏移）：现有 M5 bars 数据可直接计算，补入 review。【候选假设：有助于区分"方向对但档位差"与"方向错"，仅为测量】
- C2 prompt_version 效果对比：1.1.1 上线后观察 REJECTED 率变化，compute_context_stats 已支持按 prompt_version 分组（review.py:211）。【事实：机制已具备】

### D. 运维

- D1 **git 提交**：当前 17+ 修改/未跟踪文件全部未提交，是最大单点风险（事实）。建议立即提交。
- D2 calendar.json 周更负担：设置 `XAU_CONSOLE_CALENDAR_URL` 自动拉取（功能已有未启用，事实）。
- D3 损坏文件目前被容忍但不会被主动清出 jobs 目录（keep_minimum 保护内）；量小，暂不处理（事实）。

### E. 前端（可选）

- E1 相邻简报 delta 高亮（方向/档位变化）：数据均在，纯前端。【候选】
- E2 MODEL 阶段进度感：elapsed 已每秒更新；进一步是流式，见 B3。

## 四、明确不做（NO-GO，维持纪律）

- 不为提速绕过闸门或放宽 validator（中文契约/证据链是系统核心不变量）。
- 不把复盘统计当作"策略有效"证据；任何方向性结论需严格因果验证。
- 不引入盘中 DXY/白银联动数据源（yfinance DX=F 等）进闸门：可靠性未验证，当前最多做背景层候选。
